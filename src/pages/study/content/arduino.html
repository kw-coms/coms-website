0. 시작하기

아두이노가 무엇인지 알아보고, 준비물을 챙겨 첫 프로그램을 보드에 올려봅니다.

아두이노란?

아두이노는 작은 컴퓨터가 올라간 전자 부품 보드입니다. 정확히는 마이크로컨트롤러(microcontroller)라는 작은 칩이 핵심인데, 우리가 쓰는 PC와 달리 윈도우 같은 운영체제 없이 내가 올린 프로그램 하나만 전원이 켜져 있는 동안 계속 실행합니다.

하는 일은 언제나 비슷해요. 센서로 세상의 값을 읽고(입력) → 코드로 판단하고 → LED, 모터, 부저를 움직입니다(출력). 자동으로 켜지는 가로등, 거리를 알려주는 주차 센서 같은 장치가 모두 이 구조예요.

이 스터디에서 쓰는 Arduino UNO R3의 핵심 사양입니다. 외울 필요는 없고, "핀이 이 정도 있구나" 정도만 알아두세요.

Arduino IDE 설치와 설정

아두이노 프로그램(스케치)을 쓰고 보드에 올리는 공식 편집기가 Arduino IDE입니다. 이 글은 최신 버전인 IDE 2.x 기준이에요.

  1. arduino.cc/en/software에서 내 운영체제에 맞는 Arduino IDE 2를 내려받아 설치합니다.
  2. USB 케이블로 보드와 PC를 연결합니다. 보드에 초록색 전원 LED(ON)가 켜지면 정상이에요.
  3. IDE를 열고 도구(Tools) → 보드(Board) → Arduino AVR Boards → Arduino Uno를 선택합니다.
  4. 도구 → 포트(Port)에서 보드가 연결된 포트를 고릅니다. Windows는 COM3처럼, macOS는 /dev/cu.usbmodem… 또는 /dev/cu.usbserial…처럼, Linux는 /dev/ttyACM0 또는 /dev/ttyUSB0처럼 보입니다. 케이블을 뺐다 꽂았을 때 새로 생기는 항목이 내 보드예요.
IDE 화면의 버튼 두 개왼쪽 위의 체크(✓) = 확인(Verify)은 코드를 컴파일해 오류만 검사하고, 바로 옆 화살표(→) = 업로드(Upload)는 컴파일 후 보드에 올립니다. 오른쪽 위 돋보기 모양은 시리얼 모니터(3장)입니다.

첫 업로드: Blink

아두이노 보드에는 13번 핀에 연결된 LED가 이미 달려 있어요(보드에 L이라고 적힌 작은 LED). 회로를 만들 필요 없이 코드만으로 첫 성공을 맛볼 수 있습니다.

  1. IDE에서 파일(File) → 새 스케치를 열고 내용을 모두 지운 뒤 아래 코드를 붙여넣습니다. (또는 파일 → 예제 → 01.Basics → Blink를 열어도 같은 내용이에요.)
  2. 업로드(→) 버튼을 누릅니다. 하단에 Done uploading.이 뜨면 성공입니다.
  3. 보드의 L LED가 1초 간격으로 깜빡이면 완성!
// 보드에 달린 내장 LED(13번)를 1초 간격으로 깜빡입니다.
void setup() {
  pinMode(LED_BUILTIN, OUTPUT);   // LED_BUILTIN = 13번 핀
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);  // 켜기
  delay(1000);                      // 1000ms = 1초 기다리기
  digitalWrite(LED_BUILTIN, LOW);   // 끄기
  delay(1000);
}

지금은 한 줄 한 줄을 다 이해하지 않아도 됩니다. 1장에서 하나씩 뜯어볼 거예요. 먼저 숫자 1000을 200으로 바꾸고 다시 업로드해서 깜빡임이 빨라지는지 확인해 보세요.

업로드가 안 돼요?빨간 글씨로 not in sync나 포트 오류가 나오면 보드·포트 선택, 케이블, 드라이버 문제일 가능성이 큽니다. 8장 "막힐 때"에 점검 순서를 정리해 두었으니 거기부터 확인하세요.

1. 기본 구조와 회로 기초

모든 스케치의 뼈대인 setup()과 loop(), 그리고 LED를 안전하게 켜기 위한 전기 기초를 배웁니다.

1-1setup()과 loop()

아두이노 스케치에는 반드시 있어야 하는 함수가 두 개 있습니다. 이 둘만 있으면 일단 스케치가 성립해요.

void setup() {
  // 전원을 켜거나 리셋했을 때 딱 한 번 실행
  // 핀 모드 설정, 시리얼 시작 같은 "준비 작업"
}

void loop() {
  // setup()이 끝난 뒤 전원이 꺼질 때까지 계속 반복
  // 실제 동작은 여기에
}

요리에 비유하면 setup()은 "재료 꺼내고 불 켜기", loop()은 "계속 볶기"입니다. loop()은 끝에 도달하면 처음으로 돌아가 다시 실행됩니다. 이 반복이 아두이노의 가장 큰 특징이에요.

Blink에서 썼던 세 가지 함수를 정리합니다.

함수역할예
pinMode(핀, 모드)핀을 출력/입력으로 설정. 보통 setup()에서 한 번pinMode(8, OUTPUT);
digitalWrite(핀, 값)출력 핀을 HIGH(5V) 또는 LOW(0V)로digitalWrite(8, HIGH);
delay(ms)지정한 밀리초(1000ms = 1초) 동안 아무것도 안 하고 기다림delay(500);
자주 하는 실수C++은 대소문자를 구분하고 문장 끝에 세미콜론(;)이 필요합니다. digitalwrite, Delay처럼 쓰면 "not declared" 오류가 나요. 오류 메시지의 줄 번호 근처를 먼저 확인하세요. 오류는 보통 그 줄이나 바로 윗줄에 있습니다.

1-2전압 · 전류 · 저항, 이것만 알면 돼요

전기는 물이 흐르는 파이프에 비유하면 쉽습니다.

용어단위물에 비유하면아두이노에서는
전압 (V)볼트 V물이 떨어지는 높이(밀어내는 힘)HIGH = 5V, LOW = 0V (GND)
전류 (I)암페어 A, 밀리암페어 mA실제로 흐르는 물의 양핀 하나에서 안전하게 쓸 수 있는 건 약 20mA 이하
저항 (R)옴 Ω, 킬로옴 kΩ파이프의 좁은 구간전류를 줄여서 부품을 보호

세 값은 옴의 법칙으로 이어집니다. 이것 하나면 이 스터디의 계산은 거의 다 풀려요.

전압(V) = 전류(I) × 저항(R)      ←  I = V / R

예) 5V를 저항 1000Ω(= 1kΩ)에 걸면
    I = 5 / 1000 = 0.005A = 5mA

GND(그라운드)는 전압의 기준점, 즉 0V입니다. 전류는 항상 전원(+) → 부품 → GND(−)로 흘러서 고리(회로)가 닫혀야 흐릅니다. 회로(circuit)라는 말이 "빙 도는 길"이라는 뜻이에요. 그래서 모든 부품 연결에는 GND 쪽 선이 반드시 필요합니다.

1-3LED의 극성과 저항이 필요한 이유

LED(발광 다이오드)는 방향이 있는 부품입니다. 전류가 한쪽으로만 흐르고, 거꾸로 꽂으면 켜지지 않아요(보통은 망가지지 않지만 오래 반대로 연결하는 건 피하세요).

  • 긴 다리 = 애노드(+): 전원 쪽(아두이노 핀 쪽)에 연결
  • 짧은 다리 = 캐소드(−): GND 쪽에 연결. LED 몸통에서 테두리가 납작하게 깎인 쪽도 캐소드예요.

그리고 LED에는 반드시 저항을 직렬로 달아야 합니다. LED는 켜지고 나면 전류에 대한 저항이 거의 없는 부품이라, 저항 없이 5V를 걸면 전류가 한도 없이 커져서 LED나 아두이노 핀이 망가질 수 있어요.

빨간 LED는 켜졌을 때 자기 자신이 약 2V를 가져갑니다(색에 따라 2~3V). 나머지 전압을 저항이 맡는다고 생각하고 계산해 봅시다.

저항에 걸리는 전압 = 5V − 2V(LED) = 3V
I = 3V / 220Ω ≈ 0.0136A = 약 13.6mA   →  LED도 핀도 안전

저항을 1kΩ으로 바꾸면: I = 3 / 1000 = 3mA   →  안전하지만 좀 어두움
저항 값 고르기이 스터디에서는 LED에 220Ω(빨-빨-갈-금 띠)을 씁니다. 330Ω도 괜찮고, 값이 클수록 어두워져요. 저항은 방향이 없어서 LED의 앞에 달든 뒤에 달든 상관없습니다.

1-4브레드보드: 안에서 어디가 연결되어 있을까

브레드보드는 납땜 없이 부품 다리를 구멍에 꽂아 회로를 만드는 판입니다. 핵심은 구멍들이 속에서 어떻게 이어져 있는가예요.

  • 가운데 홈을 기준으로 위쪽과 아래쪽이 분리되어 있습니다.
  • 번호가 같은 세로 한 줄의 5칸(위쪽 a~e, 아래쪽 f~j)은 안쪽에서 서로 연결되어 있어요. 같은 줄에 꽂은 두 부품 다리는 선으로 이은 것과 같습니다.
  • 가운데 홈의 위와 아래는 연결되어 있지 않습니다. 그래서 칩이나 버튼을 홈을 가로질러 꽂는 거예요.
  • 맨 바깥쪽 빨강(+)·파랑(−) 줄은 가로로 쭉 연결된 전원 레일입니다. 5V와 GND를 여기에 연결해 두면 편해요. (일부 큰 브레드보드는 레일이 가운데서 끊겨 있으니 주의)
꼭 지킬 순서회로를 만들거나 고칠 때는 USB를 뽑은 상태에서 하세요. 전원이 들어온 채로 선을 꽂다가 실수로 5V와 GND가 닿으면 보드가 상할 수 있습니다.

1-5외부 LED 깜빡이기

이제 직접 회로를 만들어 봅시다. 디지털 8번 핀이 HIGH가 되면 5V가 나오고, 그 전류가 저항 → LED → GND를 지나 한 바퀴를 돌아 LED가 켜집니다.

부품 핀연결할 곳설명
저항 한쪽 다리아두이노 D8점퍼선으로 연결
저항 다른 다리LED 긴 다리(+)브레드보드에서 같은 세로줄에 꽂기
LED 짧은 다리(−)아두이노 GND점퍼선으로 연결

배선을 마쳤으면 아래 스케치를 업로드합니다. 0장의 Blink와 거의 같지만, 핀 번호에 이름을 붙인 것이 달라요.

// 8번 핀에 연결한 외부 LED 깜빡이기
const int LED_PIN = 8;   // 핀 번호에 이름을 붙여두면 바꾸기 쉽다

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(500);
  digitalWrite(LED_PIN, LOW);
  delay(500);
}
  • const int LED_PIN = 8; — const는 "바뀌지 않는 값"이라는 뜻입니다. 이름을 붙여 두면 나중에 핀을 옮길 때 이 한 줄만 고치면 돼요. 코드 중간에 8이 여러 번 나오면 하나 놓치기 쉽습니다.
  • int는 정수를 담는 자료형이에요. 다음 장부터 float(소수), bool(참/거짓), unsigned long(큰 양수) 등도 나옵니다.
안 켜질 때 체크① LED 방향이 반대는 아닌지(긴 다리가 저항 쪽) ② 저항과 LED가 같은 세로줄에 꽂혀 있는지 ③ GND 선이 빠지지 않았는지 ④ 코드의 핀 번호와 실제 꽂은 핀이 같은지.

2. 디지털 입력

지금까지는 아두이노가 내보내기만 했다면, 이제 버튼으로 바깥 세상의 신호를 읽어 봅니다.

2-1버튼과 INPUT_PULLUP

디지털 입력은 핀의 전압이 HIGH(5V쯤)인지 LOW(0V쯤)인지를 읽는 것입니다. 버튼은 "누르면 두 다리가 연결되는 스위치"라서, 한쪽을 핀에 연결하고 다른 쪽을 GND에 연결하면 누를 때 그 핀이 GND와 이어져 LOW가 됩니다.

문제는 안 눌렀을 때입니다. 핀이 아무 데도 연결되지 않은 상태(플로팅)가 되면 주변 전기 잡음 때문에 HIGH와 LOW 값이 제멋대로 나옵니다. 그래서 안 누른 동안 핀을 5V 쪽으로 살짝 당겨 두는 풀업(pull-up) 저항이 필요한데, 아두이노는 이 저항을 칩 안에 갖고 있어요. 켜는 방법은 한 줄입니다.

pinMode(2, INPUT_PULLUP);   // 2번 핀을 입력으로 + 내부 풀업 저항 켜기
상태핀 전압digitalRead(2)
버튼 안 누름풀업 저항이 5V로 당김HIGH
버튼 누름GND와 직접 연결LOW
거꾸로예요!INPUT_PULLUP에서는 눌렀을 때가 LOW입니다. "누르면 1(HIGH)일 것 같은데"라는 직관과 반대라서 처음엔 누구나 헷갈려요. 코드를 if (digitalRead(BTN_PIN) == LOW)처럼 써서 "눌렸으면"이라고 읽으세요.
풀다운은요?반대로 5V에 버튼을 달고 10kΩ 저항으로 GND에 당겨 두는 풀다운 방식도 있습니다(누르면 HIGH). 하지만 외부 저항이 필요하고 배선이 늘어나서, 이 스터디에서는 부품이 필요 없는 INPUT_PULLUP으로 통일합니다.

2-2버튼으로 LED 켜기

1장의 LED 회로(D8)는 그대로 두고, 버튼을 D2와 GND 사이에 연결합니다. 택트 스위치는 다리가 4개인데, 같은 변의 두 다리끼리는 안쪽에서 항상 이어져 있고 누르면 양쪽 변이 모두 연결됩니다. 브레드보드의 가운데 홈을 가로질러 꽂으면 양쪽 변이 서로 다른 세로줄에 걸려서 잘 동작해요.

부품 핀연결할 곳설명
버튼 한쪽 다리아두이노 D2입력 신호
버튼 반대쪽 다리아두이노 GND눌렀을 때 D2를 LOW로 만들어 줌
LED 회로1장과 같음 (D8 → 220Ω → LED → GND)그대로 유지
버튼 다리 고르는 법택트 스위치의 같은 변에 있는 두 다리는 이미 연결되어 있습니다. 한쪽 변의 다리 하나를 D2로, 반대쪽 변의 다리 하나를 GND로 연결해야 해요(표의 "한쪽 다리"와 "반대쪽 다리"가 이 뜻입니다). 같은 변의 두 다리를 쓰면 누르든 안 누르든 항상 연결된 상태가 됩니다.
// 버튼을 누르고 있는 동안만 LED가 켜진다
const int BTN_PIN = 2;
const int LED_PIN = 8;

void setup() {
  pinMode(BTN_PIN, INPUT_PULLUP);  // 내부 풀업 저항 사용
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  if (digitalRead(BTN_PIN) == LOW) {   // 눌렀을 때 LOW!
    digitalWrite(LED_PIN, HIGH);
  } else {
    digitalWrite(LED_PIN, LOW);
  }
}

버튼을 누르고 있는 동안만 LED가 켜지고, 떼면 꺼집니다. if ... else는 "조건이 참이면 앞 블록, 아니면 뒷 블록을 실행"입니다. ==(같다)와 =(대입)을 구분하세요. 조건 안에 = 하나만 쓰는 건 흔한 실수입니다.

2-3토글과 간단한 디바운스

이번엔 한 번 누를 때마다 켜짐 ↔ 꺼짐이 바뀌는 스위치를 만들어 봅니다. 아이디어는 간단해요. LED 상태를 기억하는 변수 ledOn을 두고, 버튼이 눌릴 때마다 ledOn = !ledOn;으로 뒤집습니다. (!는 "반대로")

그런데 그냥 만들면 이상한 일이 생깁니다. 실제 버튼은 접점이 닿는 순간 수 밀리초 동안 연결/끊김이 여러 번 번갈아 일어나는 떨림(바운스, bounce)이 있어요. 사람 눈에는 한 번 눌렀지만, 아두이노(1초에 수만 번 확인)는 "눌렀다 뗐다"를 여러 번 읽어서 토글이 여러 번 일어납니다. 켜졌다 꺼졌다 불규칙해 보이는 이유예요. 이 떨림을 무시하는 것을 디바운스(debounce)라고 합니다.

방법 1. delay로 간단히

눌린 걸 감지하면 잠깐 기다려 떨림을 넘기고, 손을 뗄 때까지 기다린 뒤 다시 잠깐 기다립니다. 코드가 짧아서 입문용으로 충분해요.

// 누를 때마다 LED 켜짐/꺼짐 전환 (delay로 만든 쉬운 버전)
const int BTN_PIN = 2;
const int LED_PIN = 8;
bool ledOn = false;

void setup() {
  pinMode(BTN_PIN, INPUT_PULLUP);
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  if (digitalRead(BTN_PIN) == LOW) {        // 눌림 감지
    ledOn = !ledOn;                         // true <-> false 뒤집기
    digitalWrite(LED_PIN, ledOn ? HIGH : LOW);

    delay(30);                              // 떨림(바운스)이 지나가길 기다림
    while (digitalRead(BTN_PIN) == LOW) {   // 손을 뗄 때까지 대기
    }
    delay(30);                              // 뗄 때의 떨림도 넘기기
  }
}

단점은 delay와 while로 기다리는 동안 아두이노가 다른 일을 못 한다는 점입니다. 버튼을 누르고 있는 동안 다른 LED를 깜빡이고 싶다면 안 돼요.

방법 2. millis()로 시간 재기

millis()는 보드가 켜진 뒤 지나간 시간을 밀리초로 알려주는 함수입니다(시계를 읽기만 할 뿐 멈추지 않아요). "값이 바뀐 시각"을 기록해 두고 30ms 넘게 같은 값이 유지되면 진짜 변화로 인정하는 방식이에요.

// 누를 때마다 LED 전환 (millis로 만든 디바운스 버전)
const int BTN_PIN = 2;
const int LED_PIN = 8;
const unsigned long DEBOUNCE_MS = 30;

bool ledOn = false;
int lastReading = HIGH;          // 바로 직전에 읽은 값
int stableState = HIGH;          // 떨림이 가라앉은 뒤 확정된 값
unsigned long lastChangeTime = 0;

void setup() {
  pinMode(BTN_PIN, INPUT_PULLUP);
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  int reading = digitalRead(BTN_PIN);

  if (reading != lastReading) {          // 값이 바뀌었다 -> 시간 기록
    lastChangeTime = millis();
    lastReading = reading;
  }

  // 30ms 넘게 같은 값이 유지되면 "진짜 변화"로 인정
  if (millis() - lastChangeTime > DEBOUNCE_MS && reading != stableState) {
    stableState = reading;
    if (stableState == LOW) {            // 눌리는 순간에만 토글
      ledOn = !ledOn;
      digitalWrite(LED_PIN, ledOn ? HIGH : LOW);
    }
  }
}
  • unsigned long은 0 이상의 큰 정수 자료형입니다. millis()의 값이 이 타입이라 시간을 담는 변수는 이걸 써야 해요. int에 담으면 약 32초 뒤에 넘쳐서 이상해집니다.
  • millis() - lastChangeTime처럼 현재 시각에서 기록해 둔 시각을 빼서 경과 시간을 구하는 패턴은 7장 프로젝트에서도 다시 씁니다.
  • ledOn ? HIGH : LOW는 "ledOn이 참이면 HIGH, 아니면 LOW"를 한 줄로 쓰는 삼항 연산자입니다.
어느 걸 쓸까?지금은 방법 1로 충분합니다. 방법 2는 "기다리는 동안에도 다른 일을 하는" 코드를 만들 때 필수라서, 어렵게 느껴지면 일단 읽어만 두고 7장에서 다시 돌아와도 괜찮아요.

3. 시리얼 통신

아두이노 속 값을 PC 화면으로 꺼내 보는 방법입니다. 이후 모든 장에서 "지금 값이 뭐지?"를 확인할 때 쓰는 가장 중요한 디버깅 도구예요.

3-1Serial.begin과 print / println

아두이노는 화면이 없어서 내부 변수가 어떤 값인지 눈으로 볼 수 없습니다. 그래서 USB 케이블을 통해 PC로 글자를 보내는 시리얼 통신을 씁니다. 사용법은 세 단계입니다.

  1. setup()에서 Serial.begin(9600);로 통신을 시작합니다. 9600은 보드레이트(1초에 보내는 비트 수)로, 보내는 쪽과 받는 쪽이 같아야 해요.
  2. Serial.print(값)은 출력만, Serial.println(값)은 출력하고 줄바꿈까지 합니다.
  3. IDE의 시리얼 모니터를 열어서 확인합니다.
int count = 0;

void setup() {
  Serial.begin(9600);              // 보드레이트 9600
  Serial.println("Hello, Arduino!");
}

void loop() {
  Serial.print("count = ");        // print: 줄바꿈 없음
  Serial.println(count);           // println: 출력 후 줄바꿈
  count++;
  delay(1000);
}

업로드한 뒤 오른쪽 위 돋보기 아이콘(도구 → 시리얼 모니터, 단축키 Ctrl+Shift+M, macOS는 Cmd+Shift+M)을 누르면 1초마다 한 줄씩 나타납니다.

Hello, Arduino!
count = 0
count = 1
count = 2
count = 3
시리얼 모니터 설정창 오른쪽 아래의 속도 드롭다운이 코드의 Serial.begin() 값(여기선 9600 baud)과 같아야 글자가 제대로 보입니다. 모니터를 열면 보드가 자동으로 리셋되어 setup()이 처음부터 다시 실행되는 것도 알아두세요.
한글 대신 영어로시리얼로 보내는 글자는 영어와 숫자로 쓰는 게 편합니다. 보드나 도구에 따라 한글이 깨져 보일 수 있고, 어차피 디버깅용이라 짧은 영어 단어면 충분해요. 한글은 주석으로 마음껏 쓰세요.
0번, 1번 핀은 피하세요디지털 0번(RX)과 1번(TX)은 시리얼 통신이 쓰는 핀입니다. 여기에 부품을 연결하면 업로드가 실패하거나 시리얼이 꼬일 수 있어요. 이 스터디의 모든 회로는 2번 이상 핀을 씁니다.

3-2시리얼 모니터 활용과 플로터

2장의 버튼 회로(D2와 GND)를 그대로 두고, 버튼 상태가 바뀔 때만 출력해 봅시다. 값이 바뀌었는지 알려면 이전 값을 따로 기억해 두고 비교하면 돼요.

// 버튼 상태가 "바뀔 때만" 알려주기
const int BTN_PIN = 2;
int lastState = HIGH;

void setup() {
  Serial.begin(9600);
  pinMode(BTN_PIN, INPUT_PULLUP);
}

void loop() {
  int state = digitalRead(BTN_PIN);
  if (state != lastState) {          // 이전과 다를 때만
    if (state == LOW) {
      Serial.println("PRESSED");
    } else {
      Serial.println("RELEASED");
    }
    lastState = state;
  }
}

숫자가 시간에 따라 변하는 모양을 그래프로 보고 싶다면 시리얼 플로터(도구 → 시리얼 플로터)를 씁니다. 숫자를 이름:값 형태로 쉼표로 구분해 한 줄에 내보내면 이름별로 선이 그려져요. 시리얼 모니터와 플로터는 같은 포트를 쓰므로 한 번에 하나만 열 수 있습니다.

// 시리얼 플로터용: "이름:값" 형태로 쉼표로 구분해 출력
void setup() {
  Serial.begin(9600);
}

void loop() {
  int saw = (millis() / 10) % 100;   // 0~99를 반복하는 톱니파
  int inv = 100 - saw;               // 반대로 움직이는 값

  Serial.print("saw:");
  Serial.print(saw);
  Serial.print(",");
  Serial.print("inv:");
  Serial.println(inv);
  delay(20);
}

4. 아날로그 입력과 PWM

켜짐/꺼짐뿐 아니라 "중간 값"을 읽고(analogRead), 내보내는(analogWrite) 방법을 배웁니다.

4-1analogRead: 0~5V를 숫자로

디지털 입력은 HIGH/LOW 두 가지뿐이지만, 세상의 많은 값(빛 밝기, 온도, 손잡이 위치)은 연속적입니다. 아두이노 A0~A5 핀에는 전압을 숫자로 바꿔 주는 ADC(아날로그-디지털 변환기)가 있어서 이런 값을 읽을 수 있어요.

  • analogRead(A0)은 0V → 0, 5V → 1023 사이의 정수를 돌려줍니다. (UNO의 ADC는 10비트라서 2를 10번 곱한 1024단계)
  • 한 단계는 약 5V ÷ 1023 ≈ 4.9mV입니다.
  • 전압으로 되돌리려면 값 × 5.0 / 1023.0. (5.0처럼 소수점을 붙여야 소수로 계산돼요. 정수끼리 나누면 소수점이 잘립니다.)

입력 부품으로 10kΩ 가변저항(포텐셔미터)을 씁니다. 다리가 3개이고, 가운데 다리의 전압이 손잡이를 돌리는 만큼 0V~5V 사이에서 변합니다.

가변저항 핀연결할 곳설명
왼쪽 다리아두이노 5V한쪽 끝에 전원
가운데 다리아두이노 A0손잡이 위치에 따라 변하는 값을 읽는 선
오른쪽 다리아두이노 GND다른 쪽 끝은 GND

왼쪽/오른쪽을 서로 바꾸면 돌리는 방향과 값의 증감이 반대가 될 뿐 고장은 아닙니다. 업로드하고 시리얼 모니터를 열어 손잡이를 돌려 보세요.

// 가변저항 값을 읽어 시리얼 모니터에 출력
const int POT_PIN = A0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int raw = analogRead(POT_PIN);          // 0 ~ 1023
  float volts = raw * 5.0 / 1023.0;       // 전압으로 환산
  Serial.print("raw = ");
  Serial.print(raw);
  Serial.print("   volts = ");
  Serial.println(volts, 2);               // 소수 둘째 자리까지
  delay(200);
}

4-2map(): 범위 바꾸기

0~1023으로 읽은 값을 "0~255(밝기)"나 "0~180(각도)"처럼 다른 범위로 비례해서 바꾸고 싶을 때가 아주 많습니다. 그 일을 해주는 함수가 map입니다.

int duty = map(raw, 0, 1023, 0, 255);
//             값  원래최소 원래최대 바꿀최소 바꿀최대
  • map(512, 0, 1023, 0, 255)는 약 127(절반쯤)입니다.
  • 정수만 다루므로 결과의 소수점은 버려집니다.
  • 범위 밖의 값을 넣으면 밖의 값이 나옵니다(예: 1100이 들어가면 255를 넘음). 범위를 지켜야 하면 constrain(값, 최소, 최대)로 잘라 주세요.

4-3analogWrite와 PWM

반대로 아두이노가 중간 전압을 내보낼 수 있을까요? UNO에는 진짜 아날로그 출력이 없습니다. 대신 PWM(Pulse Width Modulation)이라는 방법으로 흉내 냅니다. 핀을 1초에 약 490번(5, 6번 핀은 약 980번) 아주 빠르게 켰다 껐다 하면서 켜져 있는 시간의 비율(듀티)을 바꾸는 거예요. LED는 너무 빨리 깜빡이면 눈에 보이지 않고 평균 밝기만 느껴집니다.

PWM이 되는 핀만 써요UNO에서 analogWrite가 되는 핀은 보드에 ~ 표시가 있는 3, 5, 6, 9, 10, 11번 핀뿐입니다. 다른 핀에서는 128 이상이면 HIGH, 미만이면 LOW로만 동작해요. 그리고 값 범위는 0~255입니다(1023이 아님!). 또 analogWrite에 쓰는 핀은 pinMode(핀, OUTPUT)을 해 두세요.

LED를 D9(PWM 핀)에 연결하고(1장 회로의 D8 선을 D9로 옮기면 됩니다), 서서히 밝아졌다 어두워지는 코드를 올려 보세요.

// LED가 서서히 밝아졌다 어두워지기 (9번은 PWM 핀)
const int LED_PIN = 9;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  for (int duty = 0; duty <= 255; duty++) {     // 점점 밝게
    analogWrite(LED_PIN, duty);
    delay(5);
  }
  for (int duty = 255; duty >= 0; duty--) {     // 점점 어둡게
    analogWrite(LED_PIN, duty);
    delay(5);
  }
}

for 문의 구조는 for (시작; 계속할 조건; 한 번 끝날 때 할 일)입니다. duty++는 duty = duty + 1과 같아요.

입력(가변저항, A0)과 출력(LED, D9)을 합칩니다. 회로는 위에서 만든 것을 그대로 한 판에 모으면 돼요.

// 가변저항을 돌려 LED 밝기 조절
const int POT_PIN = A0;

void setup() {
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(9600);

void loop() {

5. 센서와 액추에이터

거리를 재는 초음파 센서, 각도를 정하는 서보 모터, 소리를 내는 부저를 하나씩 다룹니다. 이 셋이 7장 프로젝트의 재료예요.

5-1초음파 센서 HC-SR04

박쥐처럼 사람 귀에 안 들리는 초음파(40kHz)를 쏘고, 물체에 부딪혀 돌아오는 시간을 재서 거리를 계산하는 센서입니다. 측정 범위는 약 2cm ~ 400cm이고 5V로 동작해요.

HC-SR04 핀연결할 곳설명
VCC아두이노 5V전원 (3.3V가 아니라 5V!)
Trig아두이노 D7"초음파 쏴" 신호를 보내는 입력
Echo아두이노 D6돌아올 때까지의 시간을 HIGH 길이로 알려주는 출력
GND아두이노 GND접지

동작 순서는 다음과 같습니다.

  1. Trig 핀을 10µs(마이크로초) 동안 HIGH로 만들면 센서가 초음파를 발사합니다.
  2. 센서는 Echo 핀을 HIGH로 올리고, 소리가 돌아오면 LOW로 내립니다. 즉 Echo가 HIGH였던 시간 = 소리가 갔다 오는 데 걸린 시간이에요.
  3. 그 시간을 pulseIn(ECHO_PIN, HIGH)로 µs 단위로 잽니다.

소리의 속도는 약 340m/s = 0.034cm/µs입니다. 물체까지 갔다가 되돌아온 시간이므로 2로 나눠야 편도 거리가 나옵니다.

거리(cm) = 시간(µs) × 0.034 / 2

예) 1000µs 걸렸다면:  1000 × 0.034 / 2 = 17cm
// HC-SR04 초음파 센서로 거리(cm) 측정
const int TRIG_PIN = 7;
const int ECHO_PIN = 6;

// 거리를 cm로 돌려준다. 측정 실패(범위 밖/반사 없음)면 -1
float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);      // 10µs 동안 HIGH = "초음파 쏴!"
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  // ECHO가 HIGH인 시간(µs)을 잰다. 30000µs(30ms) 안에 안 오면 포기 -> 0
  unsigned long duration = pulseIn(ECHO_PIN, HIGH, 30000UL);
  if (duration == 0) {
    return -1;
  }
  return duration * 0.034 / 2;       // 왕복이라서 2로 나눔
}

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  Serial.begin(9600);
}

void loop() {
  float cm = readDistanceCm();
  if (cm < 0) {
    Serial.println("out of range");
  } else {
    Serial.print(cm, 1);
    Serial.println(" cm");
  }
  delay(100);
}

  • pulseIn(핀, 상태, 제한시간)은 핀이 해당 상태(HIGH)로 유지된 시간을 µs로 돌려줍니다. 세 번째 인자 제한시간을 꼭 넣으세요. 안 넣으면 반사가 없을 때 기본 1초나 기다려서 프로그램이 멈춘 듯 보여요. 30000µs(30ms)는 약 5m에 해당하므로 센서 범위(4m)를 충분히 덮습니다.
  • 제한시간 안에 소리가 안 돌아오면 0을 돌려줍니다. 그래서 0이면 "측정 실패"로 취급해 -1을 돌려주도록 했습니다. 이 처리를 안 하면 0 × 0.034 / 2 = 0cm로 계산되어 "바로 앞에 있다"는 엉뚱한 결과가 나옵니다.
  • 측정 사이에는 최소 수십 ms 간격을 두세요(위 코드는 100ms). 너무 빨리 반복하면 이전 소리의 메아리를 읽습니다.
  • 2cm보다 가깝거나, 천이나 스펀지처럼 소리를 흡수하는 물체, 비스듬한 면은 잘 안 잡힙니다. 센서 앞의 평평한 책이나 손바닥으로 테스트해 보세요.
값이 ±1cm쯤 흔들려도 정상이에요이 센서는 온도와 표면 상태에 따라 오차가 있고 값이 조금씩 튑니다. 정밀 측정이 아니라 "대략 몇 cm"를 알려주는 도구라고 생각하세요.

5-2서보 모터 (SG90)

서보 모터는 "몇 도로 가라"고 시키면 그 각도로 가서 멈추는 모터입니다. SG90은 0도~180도 범위를 움직이고, 로봇 팔이나 센서 회전대에 많이 쓰여요. 제어는 라이브러리를 쓰면 아주 쉽습니다.

빨강아두이노 5V전원

  • Servo myServo; — 서보 하나를 담당하는 객체(변수)를 만듭니다. 서보가 여러 개면 이름을 달리해 여러 개 만들어요.
  • myServo.attach(9); — 이 객체를 9번 핀에 연결합니다. setup()에서 한 번.
  • myServo.write(90); — 90도로 이동합니다. 0~180 사이의 값을 씁니다.
// 서보를 0도 -> 180도 -> 0도로 왕복시키기
#include <Servo.h>

Servo myServo;
const int SERVO_PIN = 9;

void setup() {
  myServo.attach(SERVO_PIN);
}

void loop() {
  for (int angle = 0; angle <= 180; angle += 2) {
    myServo.write(angle);
    delay(15);                 // 서보가 움직일 시간
  }
  for (int angle = 180; angle >= 0; angle -= 2) {
    myServo.write(angle);
    delay(15);
  }
}

서보가 천천히 왕복하면 성공입니다. 이제 3장·4장의 가변저항과 map()을 합쳐서 손잡이로 서보를 조종해 봅시다. 가변저항은 4장과 같은 배선(5V / A0 / GND)으로 연결합니다.

// 가변저항으로 서보 각도 조종하기
#include <Servo.h>

Servo myServo;
const int SERVO_PIN = 9;

  myServo.attach(SERVO_PIN);
}

서보를 쓸 때 알아둘 것① Servo 라이브러리를 쓰면 UNO에서 9번과 10번 핀의 analogWrite(PWM)가 동작하지 않습니다. 서보와 PWM LED를 같이 쓸 때는 LED를 3, 5, 6, 11번에 연결하세요. ② 서보는 움직일 때 전류를 많이 씁니다. 작은 SG90 한 개를 가볍게 움직이는 건 USB 전원으로 되지만, 서보가 여러 개이거나 무거운 걸 움직이면 보드가 갑자기 리셋되거나 서보가 덜덜 떨릴 수 있어요. 그럴 땐 8장의 안전 수칙처럼 서보 전원을 따로 연결해야 합니다. ③ 각도의 끝(0도, 180도)에서 계속 "웅~" 소리가 나면 그 지점에서 기계적으로 막혀 있다는 뜻이니, 범위를 10~170도 정도로 줄여 주세요.

5-3피에조 부저: tone()과 noTone()

피에조 부저는 전기 신호의 떨림 속도(주파수, 단위 Hz)에 맞춰 떨면서 소리를 냅니다. 주파수가 높을수록 높은 음이에요. 부저에는 두 종류가 있습니다.

  • 패시브(수동) 부저: 신호를 주는 대로 소리가 납니다. 음 높이를 마음대로 바꿔 멜로디도 가능. 이 스터디의 tone()은 이 부저 기준이에요. 뒷면에 기판이 그대로 보이는 경우가 많습니다.
  • 액티브(능동) 부저: 안에 발진 회로가 있어서 전원만 주면 정해진 음이 납니다. digitalWrite(핀, HIGH)로 켜고 LOW로 끄면 되고, tone()을 써도 음 높이는 바뀌지 않아요. 구별하는 믿을 만한 방법은 5V와 GND에 잠깐 연결해 보는 것입니다. 혼자 삐- 하고 울리면 액티브, 조용하면 패시브예요.
부저 핀연결할 곳설명
+ (긴 다리 또는 + 표시)아두이노 D8신호
− (짧은 다리)아두이노 GND접지
  • tone(핀, 주파수) — 해당 주파수로 소리를 계속 냅니다.
  • tone(핀, 주파수, 길이ms) — 지정한 시간만 낸 뒤 자동으로 멈춥니다. 이 함수는 소리를 시작만 시키고 바로 다음 줄로 넘어가요. 소리가 끝나길 기다리려면 delay를 따로 써야 합니다.
  • noTone(핀) — 소리를 멈춥니다.
// 피에조 부저로 도레미파솔 연주
const int BUZZER_PIN = 8;

}

void loop() {
  for (int i = 0; i < NOTE_COUNT; i++) {
    tone(BUZZER_PIN, notes[i], 300);   // 300ms 동안 소리 (기다리지 않고 바로 다음 줄로)
    delay(400);                        // 소리 + 쉬는 시간
  }
  noTone(BUZZER_PIN);
  delay(1500);
}

6-2조도 센서 (CDS 포토레지스터)

CDS 조도 센서는 빛을 받을수록 저항이 작아지는 저항입니다. 밝은 곳에서는 수 kΩ, 어두운 곳에서는 수백 kΩ~MΩ까지 변해요. 방향(극성)이 없어서 어느 다리를 어디에 꽂아도 됩니다.

그런데 아두이노의 analogRead는 저항이 아니라 전압을 읽습니다. 저항이 변하는 부품을 그냥 핀에 연결해서는 아무것도 읽을 수 없어요. 그래서 고정 저항과 함께 전압 분배 회로(분압)를 만들어 "저항의 변화"를 "전압의 변화"로 바꿔 줍니다.

  5V
   │
 [CDS]          ← 빛에 따라 저항이 변함
   │
   ├──────→ A0   ← 이 지점(분압점)의 전압을 읽는다
   │
 [10kΩ]         ← 고정 저항
   │
  GND

A0 전압 = 5V × 10kΩ / (CDS 저항 + 10kΩ)

밝음   CDS = 1kΩ   →  5 × 10 / 11  ≈ 4.5V   →  analogRead ≈ 930
보통   CDS = 10kΩ  →  5 × 10 / 20  = 2.5V   →  analogRead ≈ 512
어두움 CDS = 100kΩ →  5 × 10 / 110 ≈ 0.45V  →  analogRead ≈ 93

CDS를 5V 쪽에 두면 밝을수록 값이 커집니다. 반대로 두면 밝을수록 작아져요. 실제 값은 센서마다 달라서 이 숫자는 어림값일 뿐이니, 먼저 시리얼 모니터로 내 센서의 값을 확인해야 합니다.

  Serial.println(ledOn ? "  LED ON" : "  LED OFF");

6-3RGB LED

// RGB LED(공통 캐소드)로 색 섞기
const int R_PIN = 9;
const int G_PIN = 10;
const int B_PIN = 11;
const bool COMMON_ANODE = false;   // 공통 애노드 LED면 true

void setColor(int r, int g, int b) {
  if (COMMON_ANODE) {              // 공통 애노드는 값이 반대 (255 = 꺼짐)
    r = 255 - r;
    g = 255 - g;
    b = 255 - b;
  }
  analogWrite(R_PIN, r);
  analogWrite(G_PIN, g);
  analogWrite(B_PIN, b);
}

void setup() {
  pinMode(R_PIN, OUTPUT);
  pinMode(G_PIN, OUTPUT);
  pinMode(B_PIN, OUTPUT);
}

void loop() {
  setColor(255, 0, 0);     delay(800);   // 빨강
  setColor(0, 255, 0);     delay(800);   // 초록
  setColor(0, 0, 255);     delay(800);   // 파랑
  setColor(255, 255, 0);   delay(800);   // 노랑 = 빨강 + 초록
  setColor(0, 255, 255);   delay(800);   // 하늘색 = 초록 + 파랑
  setColor(255, 0, 255);   delay(800);   // 보라 = 빨강 + 파랑
  setColor(255, 255, 255); delay(800);   // 흰색 (실제로는 살짝 푸르스름)
  setColor(255, 80, 0);    delay(800);   // 주황
}

이제 색이 부드럽게 한 바퀴 도는 스케치입니다. wheel(pos)는 0~255의 숫자 하나를 받아 빨강 → 초록 → 파랑 → 빨강 순으로 색을 만들어 줍니다.

// 무지개처럼 색이 부드럽게 한 바퀴 도는 RGB LED
const int R_PIN = 9;
const int G_PIN = 10;
const int B_PIN = 11;
const bool COMMON_ANODE = false;

void setColor(int r, int g, int b) {
  if (COMMON_ANODE) {
    r = 255 - r;
    g = 255 - g;
    b = 255 - b;
  }
  analogWrite(R_PIN, r);
  analogWrite(G_PIN, g);
  analogWrite(B_PIN, b);
}

// pos: 0~255 -> 빨강 -> 초록 -> 파랑 -> 다시 빨강
void wheel(int pos) {
  if (pos < 85) {
    setColor(255 - pos * 3, pos * 3, 0);
  } else if (pos < 170) {
    pos -= 85;
    setColor(0, 255 - pos * 3, pos * 3);
  } else {
    pos -= 170;
    setColor(pos * 3, 0, 255 - pos * 3);
  }
}

void setup() {
  pinMode(R_PIN, OUTPUT);
  pinMode(G_PIN, OUTPUT);
  pinMode(B_PIN, OUTPUT);
}

void loop() {
  for (int pos = 0; pos < 256; pos++) {
    wheel(pos);
    delay(20);
  }
}
저항은 꼭 달기, 색마다 밝기가 달라요저항 없이 연결하면 1장에서 본 것처럼 핀과 LED가 상할 수 있습니다. 220Ω이면 색당 약 9~14mA라 핀 하나당 권장 한도(약 20mA) 안이에요. 초록과 파랑은 빨강보다 켜질 때 전압이 높아(약 3V) 전류가 조금 작고 색 균형이 살짝 달라 보입니다. 흰색이 푸르스름하게 보이면 정상이에요.

6-4I2C LCD 16x2

LCD 1602는 16칸 × 2줄로 글자를 표시하는 화면입니다. 원래는 연결 선이 10개 이상 필요하지만, 뒤에 I2C 백팩(PCF8574 칩이 붙은 작은 기판)이 달린 제품을 쓰면 전원 2개 + 신호 2개, 총 4개 선이면 됩니다.

I2C(아이스퀘어씨)는 선 두 개로 여러 장치와 통신하는 방식입니다. SDA는 데이터, SCL은 박자(클럭) 선이고, 장치마다 고유한 주소가 있어서 같은 두 선에 여러 장치를 매달 수 있어요. UNO에서는 SDA = A4, SCL = A5로 정해져 있습니다. (보드 위쪽 AREF 옆에 SDA·SCL이라고 인쇄된 핀도 같은 선입니다.)

LCD 백팩 핀연결할 곳설명
GND아두이노 GND접지
VCC아두이노 5V전원 (3.3V 아님)
SDA아두이노 A4I2C 데이터
SCL아두이노 A5I2C 클럭
(선택) 가변저항 가운데 다리아두이노 A0아래 스케치에서 값을 표시할 때만. 양쪽 다리는 5V와 GND

1단계: 주소 찾기. I2C 장치는 제품에 따라 주소가 0x27 또는 0x3F입니다(모듈 점퍼 설정에 따라 0x20~0x27, 0x38~0x3F 중 다른 값일 수도 있어요 — 스캐너로 확인). 주소가 틀리면 아무것도 안 나오므로, 먼저 아래 스캐너 스케치로 내 LCD의 주소를 확인하세요. (Wire는 I2C를 다루는 기본 라이브러리로, 설치가 필요 없어요.)

// I2C 장치 주소 찾기
#include <Wire.h>

void setup() {
  Wire.begin();
  Serial.begin(9600);
}

void loop() {
  Serial.println("Scanning...");
  int found = 0;

  for (byte addr = 1; addr < 127; addr++) {
    Wire.beginTransmission(addr);
    if (Wire.endTransmission() == 0) {      // 0 = 응답함
      Serial.print("I2C device found at address 0x");
      if (addr < 16) {
        Serial.print("0");
      }
      Serial.println(addr, HEX);
      found++;
    }
  }

  if (found == 0) {
    Serial.println("No I2C devices found");
  } else {
    Serial.println("done");
  }
  delay(3000);
}

2단계: 글자 표시하기. 알아낸 주소를 LiquidCrystal_I2C lcd(주소, 16, 2);에 넣습니다. 0x3F가 나왔다면 0x3F로 바꾸세요.

// I2C LCD에 글자와 센서 값 표시하기
#include <Wire.h>
#include <LiquidCrystal_I2C.h>

LiquidCrystal_I2C lcd(0x27, 16, 2);   // (주소, 가로 16칸, 세로 2줄)

void setup() {
  lcd.init();         // LCD 초기화
  lcd.backlight();    // 백라이트 켜기
  lcd.setCursor(0, 0);
  lcd.print("Hello, COM's!");
}

void loop() {
  int raw = analogRead(A0);       // 가변저항을 A0에 연결했을 때
  lcd.setCursor(0, 1);            // (칸, 줄) = 둘째 줄 맨 왼쪽
  lcd.print("A0 = ");
  lcd.print(raw);
  lcd.print("    ");              // 앞 값의 남은 글자를 공백으로 지우기
  delay(200);
}
  • 가변저항을 연결하지 않으면 A0가 아무 곳에도 이어지지 않은 상태라 두 번째 줄에는 아무 숫자나 나옵니다. 정상이에요.
  • lcd.init()으로 LCD를 초기화하고 lcd.backlight()로 백라이트를 켭니다. 이 글은 Frank de Brabander 라이브러리의 init() 방식을 씁니다. 다른 I2C LCD 라이브러리는 begin()만 쓰기도 하니, 예제를 섞어 붙이지 마세요.
  • lcd.setCursor(칸, 줄)은 글자를 쓸 위치입니다. 칸은 0~15, 줄은 0~1이고 둘 다 0부터 셉니다. 그다음 lcd.print()는 Serial.print()와 똑같이 쓰면 돼요.
  • lcd.clear()는 화면 전체를 지웁니다. 하지만 자주 부르면 화면이 깜빡이므로, 값이 바뀌는 곳만 위 코드처럼 공백으로 덮어쓰기하는 것이 보기 좋아요. 공백을 빼면 값이 1000에서 99로 줄 때 990처럼 앞 글자가 남습니다.
  • 한글은 표시되지 않습니다. 영문, 숫자, 기호만 쓰세요.
켜졌는데 화면이 비어 있어요① 백팩 뒷면의 파란 가변저항(콘트라스트)을 작은 드라이버로 천천히 돌려 보세요. 이게 안 맞으면 켜져 있어도 글자가 안 보이거나 네모 칸만 보입니다. ② 주소(0x27/0x3F)가 맞는지 스캐너로 확인. ③ SDA와 SCL을 서로 바꿔 꽂지 않았는지. ④ VCC에 5V를 연결했는지. ⑤ 백팩의 백라이트 점퍼가 빠져 있지 않은지.

6-5DHT11 온습도 센서

DHT11은 온도와 습도를 하나의 데이터 선으로 알려주는 디지털 센서입니다. 센서 안에서 값을 계산해 보내 주므로 analogRead가 필요 없어요. 대신 정해진 통신 규칙이 있어서 DHT sensor library(Adafruit)를 사용합니다. DHT sensor library와 Adafruit Unified Sensor를 둘 다 설치했는지 6-1절에서 먼저 확인하세요.

제품측정 범위 / 오차읽는 간격
DHT11온도 0~50°C (±2°C), 습도 20~80% (±5%)최대 약 1초에 1번. 안전하게 2초 이상

3핀 모듈형 제품은 풀업 저항이 기판에 이미 달려 있어서 그대로 연결하면 됩니다. 센서 단품(핀 4개, 그중 하나는 사용 안 함)이라면 DATA와 VCC 사이에 10kΩ 풀업 저항을 직접 달아야 해요. 이 글은 모듈형 기준입니다.

DHT11 모듈 핀연결할 곳설명
S (또는 OUT, DATA)아두이노 D2데이터
VCC (또는 +)아두이노 5V전원
GND (또는 −)아두이노 GND접지
모듈마다 핀 순서가 달라요어떤 모듈은 S / VCC / GND, 어떤 모듈은 VCC / S / GND, GND / VCC / S 순서입니다. 기판에 인쇄된 글자를 보고 연결하세요. 전원을 반대로 꽂으면 센서가 뜨거워지며 망가질 수 있습니다.
// DHT11로 온도와 습도 읽기
#include <DHT.h>

const int DHT_PIN = 2;
DHT dht(DHT_PIN, DHT11);

void setup() {
  Serial.begin(9600);
  dht.begin();
}

void loop() {
  delay(2000);                          // DHT11은 1~2초에 한 번만 읽을 수 있다

  float h = dht.readHumidity();         // 습도 (%)
  float t = dht.readTemperature();      // 온도 (섭씨)

  if (isnan(h) || isnan(t)) {           // 읽기 실패하면 NaN
    Serial.println("DHT read failed");
    return;
  }

  Serial.print("Temp: ");
  Serial.print(t, 1);
  Serial.print(" C   Humidity: ");
  Serial.print(h, 0);
  Serial.println(" %");
}

  • DHT dht(2, DHT11); — 데이터 핀 번호와 센서 종류(DHT11)를 넣어 객체를 만듭니다. DHT22 센서라면 DHT22로 바꾸세요. dht.begin();은 setup()에서 한 번 부릅니다.
  • dht.readTemperature()는 섭씨 온도를, dht.readHumidity()는 습도(%)를 float로 돌려줍니다. 화씨는 dht.readTemperature(true).
  • 읽기에 실패하면 NaN(숫자가 아님)을 돌려주므로 isnan()으로 꼭 검사하세요. 배선이 빠지거나 너무 자주 읽을 때 생깁니다. 검사 없이 NaN을 출력하면 nan이라는 글자가 나옵니다.
  • DHT11은 정수 단위에 가까운 값을 주는 센서라서 습도를 소수점으로 표시해도 의미가 없습니다. 위 코드는 습도를 print(h, 0)으로 정수만 표시했어요.

이제 6-4절의 LCD를 같이 연결해, 컴퓨터 없이도 온습도를 보여주는 미니 기상대를 만들어 봅니다. DHT11은 D2, LCD는 A4/A5를 쓰므로 서로 핀이 겹치지 않아요. LCD 배선(GND, 5V, A4, A5)은 6-4절 그대로입니다.

부품 핀연결할 곳설명
DHT11 모듈 S / VCC / GNDD2 / 5V / GND위의 DHT11 배선 그대로
LCD GND / VCC / SDA / SCLGND / 5V / A4 / A56-4절 배선 그대로. 5V와 GND는 브레드보드 레일에서 나눠 쓰기

const int DHT_PIN = 2;
DHT dht(DHT_PIN, DHT11);

6-6조이스틱 모듈

조이스틱 모듈(KY-023 등)은 사실 가변저항 두 개(X축, Y축)와 버튼 하나를 합친 부품입니다. 4장의 가변저항과 원리가 같아요. 스틱을 움직이면 각 축의 가운데 핀 전압이 0~5V 사이에서 변하고, 스틱을 누르면 버튼이 눌립니다.

조이스틱 핀연결할 곳설명
GND아두이노 GND접지
+5V (또는 VCC)아두이노 5V전원
VRx아두이노 A0좌우(X축) 값
VRy아두이노 A1상하(Y축) 값
SW아두이노 D7스틱을 누르는 버튼. INPUT_PULLUP으로 읽음
// 조이스틱 모듈: 방향과 버튼 읽기
const int X_PIN = A0;
const int Y_PIN = A1;
const int SW_PIN = 7;

void setup() {
  pinMode(SW_PIN, INPUT_PULLUP);   // 버튼: 누르면 LOW
  Serial.begin(9600);
}

void loop() {
  int x = analogRead(X_PIN);       // 가운데쯤 512
  int y = analogRead(Y_PIN);
  bool pressed = (digitalRead(SW_PIN) == LOW);

  const char* dir = "CENTER";
  if (x < 300) {
    dir = "LEFT";
  } else if (x > 700) {
    dir = "RIGHT";
  } else if (y < 300) {
    dir = "UP";
  } else if (y > 700) {
    dir = "DOWN";
  }

  int vx = map(x, 0, 1023, -100, 100);   // -100 ~ +100 으로 바꿔 보기

  Serial.print("X=");
  Serial.print(x);
  Serial.print(" Y=");
  Serial.print(y);
  Serial.print(" vx=");
  Serial.print(vx);
  Serial.print(" SW=");
  Serial.print(pressed ? "PRESSED" : "-");
  Serial.print(" -> ");
  Serial.println(dir);
  delay(150);
}

X=118 Y=511 vx=-77 SW=- -> LEFT
X=1023 Y=508 vx=100 SW=- -> RIGHT
X=514 Y=14 vx=0 SW=- -> UP
X=513 Y=510 vx=0 SW=PRESSED -> CENTER
  • 스틱을 놓았을 때 값은 약 512(0~1023의 가운데)이지만 모듈마다 ±수십 정도 다릅니다. 그래서 "정확히 512일 때만 중앙"이라고 하지 않고, 300 이하는 한쪽, 700 이상은 반대쪽처럼 여유 있는 범위(데드존)로 판단합니다.
  • SW 버튼은 2장과 같아요. INPUT_PULLUP이므로 누르면 LOW입니다. 방향과 버튼은 따로 읽습니다.
  • map(x, 0, 1023, -100, 100)은 값을 -100(왼쪽 끝)~+100(오른쪽 끝)으로 바꿔 줍니다. 가운데는 대략 0이에요. 이렇게 하면 모터 속도나 서보 각도에 쓰기 편합니다.
위/아래, 좌/우가 반대로 나와요모듈을 놓는 방향이나 제품에 따라 UP과 DOWN, LEFT와 RIGHT가 뒤바뀌어 나올 수 있습니다. 고장이 아니에요. 코드의 "LEFT"와 "RIGHT"(또는 UP과 DOWN)를 서로 바꿔 쓰거나, 모듈을 돌려 놓으면 됩니다.

6-7DC 모터는 핀에 바로 연결하면 안 된다

5장의 서보 모터는 아두이노 5V에 연결해도 괜찮았지만, 일반 DC 모터(장난감 자동차나 선풍기에 들어 있는 모터)는 아두이노 핀에 직접 연결하면 안 됩니다. 이유는 세 가지예요.

  • 전류가 너무 큽니다. UNO의 핀 하나는 최대 40mA까지만 견디고(절대 한계), 안전하게 쓰려면 약 20mA 이하여야 합니다. 작은 DC 모터도 돌 때 100~300mA를 쓰고, 멈춰 버리면(스톨) 수백 mA~1A 이상이 흘러요. 핀이 바로 망가집니다.
  • 역전압이 생깁니다. 모터는 코일이라, 전원을 끊는 순간 반대 방향으로 높은 전압(역기전력)이 튀어나와 아두이노 칩을 상하게 할 수 있습니다.
  • 전원이 부족합니다. USB 전원은 약 500mA이고 칩 전체로도 합계 한도(약 200mA)가 있어서, 모터를 아두이노 5V로 돌리면 보드가 갑자기 리셋되거나 PC가 USB를 끊어 버릴 수 있어요.

해결책은 모터 드라이버입니다. 아두이노는 작은 신호만 보내고, 큰 전류는 드라이버가 별도 전원(건전지)에서 끌어와 모터에 공급합니다. 이 글에서는 작고 저렴한 L9110S 모터 드라이버 모듈을 씁니다. 모터 두 개(A, B)를 제어할 수 있고, 이 절에서는 A 채널 하나만 씁니다. (키트에 L298N 모듈이 있다면 다른 부품이라 핀 이름이 다르니, 이 글은 L9110S 기준으로 따라 하세요.)

드라이버 핀연결할 곳설명
VCC건전지 팩 (+) (AA 4개, 약 6V)모터용 외부 전원. 아두이노 5V에 연결하지 않기
GND건전지 팩 (−) 와 아두이노 GND 둘 다공통 접지. 브레드보드 GND 레일에 같이 꽂기
A-IA아두이노 D5방향/속도 신호 1 (PWM)
A-IB아두이노 D6방향/속도 신호 2 (PWM)
MOTOR-A 단자 2개DC 모터의 두 선극성 없음. 반대로 돌면 두 선을 서로 바꾸기

제어 방식은 간단해요. 두 신호 핀 A-IA, A-IB 중 어느 쪽에 PWM을 주느냐가 방향이고, PWM 값(0~255)이 속도입니다.

A-IA (D5)A-IB (D6)동작
PWM (0~255)LOW(0)정방향, 속도 = PWM 값
LOW(0)PWM (0~255)역방향, 속도 = PWM 값
LOWLOW정지 (모터가 힘을 빼고 자연스럽게 멈춤)

두 핀을 동시에 HIGH로 두는 조합은 모듈마다 동작이 달라서 쓰지 않는 것이 안전합니다. 5번과 6번은 PWM 핀(~)이고, 서보(9, 10번)와 tone()(3, 11번)에 영향받지 않는 핀이에요.

// L9110S 모터 드라이버로 DC 모터 속도·방향 제어
const int A_IA = 5;   // PWM 핀
const int A_IB = 6;   // PWM 핀

// speed: -255(최대 역방향) ~ 0(정지) ~ +255(최대 정방향)
void setMotor(int speed) {
  speed = constrain(speed, -255, 255);
  if (speed >= 0) {
    analogWrite(A_IA, speed);
    analogWrite(A_IB, 0);
  } else {
    analogWrite(A_IA, 0);
    analogWrite(A_IB, -speed);
  }
}

void setup() {
  pinMode(A_IA, OUTPUT);
  pinMode(A_IB, OUTPUT);
  setMotor(0);
}

void loop() {
  for (int s = 0; s <= 255; s += 5) {    // 서서히 빨라지기 (정방향)
    setMotor(s);
    delay(40);
  }
  delay(1000);
  setMotor(0);                           // 방향을 바꾸기 전에 먼저 멈추기
  delay(800);

  for (int s = 0; s >= -255; s -= 5) {   // 서서히 빨라지기 (역방향)
    setMotor(s);
    delay(40);
  }
  delay(1000);
  setMotor(0);
  delay(2000);
}
  • setMotor(speed)는 부호로 방향을, 크기로 속도를 정합니다. constrain()은 값이 -255~255를 벗어나지 않게 막아 줘요. analogWrite(핀, 0)은 그 핀을 LOW로 유지합니다.
  • 작은 DC 모터는 PWM 값이 너무 낮으면(대략 60~100 이하) 힘이 부족해 웅 소리만 나고 돌지 않습니다. 이상하게 느려 보이는 게 아니라 정상이에요.
  • 정방향에서 역방향으로 갈 때는 위 코드처럼 먼저 멈췄다가 바꾸세요. 달리다가 바로 반대로 돌리면 큰 전류가 흘러 드라이버와 건전지에 무리가 갑니다.
  • 건전지는 드라이버 데이터시트 범위(L9110S는 약 2.5~12V) 안이면 됩니다. 모터의 정격 전압(3~6V 등)을 넘지 않는 팩을 고르세요. 새 알카라인 건전지 4개는 6.4V까지 나올 수 있어요.
  • L9110S 모듈은 제조사마다 핀 순서와 이름이 조금씩 다를 수 있습니다. 위 표의 순서가 아니라 기판에 인쇄된 글자(VCC, GND, A-IA, A-IB 등)를 보고 연결하세요.
안전 수칙 - 모터는 반드시 이 순서와 규칙으로① 모터 + 드라이버를 아두이노 핀에 직접 연결 금지. 모터 전원선은 드라이버를 통해서만 연결합니다. ② 모터 전원은 건전지 팩 같은 외부 전원으로, 아두이노 5V 핀에서 가져오지 마세요. ③ 외부 전원의 GND와 아두이노 GND는 반드시 연결(공통 접지)하세요. 빠지면 신호 기준이 달라 모터가 제멋대로 움직이거나 아무 반응이 없습니다. ④ 배선은 건전지를 빼고 USB도 뽑은 상태에서 하고, 건전지 (+)와 (−)가 닿지 않게 주의하세요(단락되면 선이 뜨거워지고 건전지가 위험합니다). ⑤ 모터가 돌 때 회전축과 날개에 손, 머리카락, 선이 닿지 않게 하세요. ⑥ 모터가 막혀서 안 돌아가는데 계속 전원을 주면 모터와 드라이버가 뜨거워집니다. 바로 전원을 끄세요. ⑦ 리튬 폴리머(LiPo) 등 고용량 전지는 쓰지 말고 건전지로만 연습하세요.

✅ 확인 문제

Q1. CDS 조도 센서를 아두이노 A0에 바로 연결하지 않고 10kΩ 저항과 함께 분압 회로로 만드는 이유는?아날로그 핀은 저항이 아니라 전압을 읽기 때문입니다. CDS는 밝기에 따라 저항이 변하는 부품이라서, 고정 저항과 직렬로 연결해 "저항의 변화"를 "A0 전압의 변화"로 바꿔 줘야 합니다.
Q2. UNO에서 I2C 통신에 쓰는 SDA와 SCL은 각각 몇 번 핀이고, LCD가 안 나올 때 가장 먼저 확인할 두 가지는?SDA = A4, SCL = A5. 확인할 것은 I2C 주소(0x27 또는 0x3F)와 백팩의 콘트라스트 가변저항입니다. 주소는 I2C 스캐너 스케치로 찾을 수 있습니다.
Q3. DHT11을 읽을 때 isnan() 검사가 필요한 이유와, 읽는 간격은 어떻게 해야 할까요?읽기에 실패하면 NaN을 돌려주기 때문이고, 간격은 최소 1초 이상(안전하게 2초)으로 둡니다. 너무 자주 읽거나 배선이 빠지면 실패하며, 검사하지 않으면 nan 같은 이상한 값이 나옵니다.
Q4. 공통 캐소드 RGB LED에서 R 핀에 255, G 핀에 255, B 핀에 0을 주면 어떤 색일까요? 공통 애노드 제품이라면 코드를 어떻게 바꿔야 할까요?노랑(빨강 + 초록). 공통 애노드는 값을 반대로(255 - 값) 줘야 합니다. 공통 애노드는 공통 다리가 5V라서 색 핀이 LOW일 때 켜지기 때문입니다.
Q5. DC 모터를 아두이노 핀에 직접 연결하면 안 되는 대표 이유 두 가지와, 모터 드라이버를 쓸 때 꼭 연결해야 하는 선은?핀 허용 전류(권장 약 20mA, 절대 최대 40mA)보다 모터 전류가 훨씬 크고, 모터가 만드는 역전압이 칩을 상하게 하기 때문입니다. 외부 전원의 GND와 아두이노 GND를 연결(공통 접지)해야 합니다. 모터 전원은 건전지 팩 등 외부 전원에서 드라이버로 공급합니다.
🧩 6장 미니 과제조이스틱의 X축 값을 map()으로 -255~255로 바꿔서 setMotor()에 넣으면 스틱으로 DC 모터의 속도와 방향을 조종할 수 있어요. 가운데 근처(±30)는 데드존으로 정지시키는 것도 잊지 마세요. (힌트: 조이스틱 A0, 모터 D5/D6 - 핀이 겹치지 않습니다.)

7-2단계별로 쌓아 올리기

한 번에 다 만들면 어디가 문제인지 찾기 어렵습니다. 작은 동작 하나를 확인하고 → 다음 부품을 더하는 순서로 갑니다. 이것이 하드웨어 프로젝트의 가장 좋은 습관이에요.

1단계. 센서만 확인하기. 위 배선 중 HC-SR04만 연결하고 5장의 거리 측정 스케치(readDistanceCm)를 그대로 올립니다. 시리얼 모니터에서 손을 가까이/멀리 했을 때 숫자가 변하면 통과. 값이 계속 out of range면 배선(Trig·Echo가 바뀌지 않았는지)을 먼저 확인하세요.

2단계. 문턱값으로 부저 울리기. 부저를 연결하고, 20cm 안으로 들어오면 울리는 가장 단순한 규칙부터 만듭니다.

// 2단계: 20cm 안으로 들어오면 부저가 울린다
const int TRIG_PIN = 7;
const int ECHO_PIN = 6;
const int BUZZER_PIN = 8;

float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  unsigned long duration = pulseIn(ECHO_PIN, HIGH, 30000UL);
  if (duration == 0) {
    return -1;
  }
  return duration * 0.034 / 2;
}

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  pinMode(BUZZER_PIN, OUTPUT);
}

void loop() {
  float cm = readDistanceCm();

  if (cm > 0 && cm < 20) {        // -1(실패)은 제외하고 20cm 미만이면
    tone(BUZZER_PIN, 1000);
  } else {
    noTone(BUZZER_PIN);
  }
  delay(60);                       // 센서에게 쉴 시간 주기
}
  • cm > 0 && cm < 20은 "0보다 크고 20보다 작다". &&는 "그리고(AND)"입니다. -1(측정 실패)을 걸러내려고 cm > 0을 먼저 확인합니다.
  • 이 단계에서는 시리얼 출력이 없어도 돼요. 손을 20cm 안으로 넣으면 소리가 나고, 빼면 멈추면 통과.

3단계. 거리에 따라 간격 바꾸기 + LED. 소리 간격을 거리에 비례하게 하려면 4장에서 배운 map()을 씁니다. 거리 10~100cm를 간격 80~800ms로 바꾸는 거예요. 그리고 "마지막으로 삑 한 시각"을 millis()로 기록해 두고, 그 뒤로 간격이 지났을 때만 다음 삑을 합니다(2장의 millis 패턴!). delay(간격)로 쉬면 쉬는 동안 거리를 못 재서 반응이 느려지기 때문이에요.

7-3완성 코드

LED를 연결하고 아래 최종 코드를 올립니다. 시리얼 모니터로 거리가 찍히는 것도 확인하세요.

// 거리 경보기: 가까울수록 빨리 삐삐
const int TRIG_PIN   = 7;
const int ECHO_PIN   = 6;
const int BUZZER_PIN = 8;
const int LED_PIN    = 4;

const int  NEAR_CM = 10;        // 이보다 가까우면 계속 울림
const int  FAR_CM  = 100;       // 이보다 멀면 조용
const long MIN_INTERVAL = 80;   // 가장 빠른 삐삐 간격(ms)
const long MAX_INTERVAL = 800;  // 가장 느린 삐삐 간격(ms)
const int  BEEP_MS = 40;        // 한 번 "삑" 소리의 길이(ms)

unsigned long lastBeep = 0;     // 마지막으로 삑 한 시각

float readDistanceCm() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  unsigned long duration = pulseIn(ECHO_PIN, HIGH, 30000UL);
  if (duration == 0) {
    return -1;
  }
  return duration * 0.034 / 2;
}

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  pinMode(BUZZER_PIN, OUTPUT);
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  float cm = readDistanceCm();
  Serial.println(cm, 1);          // 확인용 (실패하면 -1.0)

  if (cm < 0 || cm > FAR_CM) {            // 측정 실패이거나 멀다 -> 조용
    noTone(BUZZER_PIN);
    digitalWrite(LED_PIN, LOW);
  } else if (cm <= NEAR_CM) {             // 아주 가깝다 -> 계속 울림
    tone(BUZZER_PIN, 1500);
    digitalWrite(LED_PIN, HIGH);
  } else {                                // 중간 -> 거리에 따라 간격 조절
    noTone(BUZZER_PIN);                    // 가까운 구간의 계속 울림이 남지 않게 먼저 끈다
    digitalWrite(LED_PIN, LOW);
    long interval = map((long)cm, NEAR_CM, FAR_CM, MIN_INTERVAL, MAX_INTERVAL);

    if (millis() - lastBeep >= (unsigned long)interval) {
      lastBeep = millis();
      digitalWrite(LED_PIN, HIGH);
      tone(BUZZER_PIN, 1000, BEEP_MS);
      delay(BEEP_MS);
      digitalWrite(LED_PIN, LOW);
    }
  }
  delay(60);
}

코드의 핵심 부분을 풀어 봅니다.

  • 설정 값을 맨 위로 — NEAR_CM, FAR_CM, MIN_INTERVAL 등을 상수로 모아 두었습니다. 반응이 너무 민감하거나 둔하면 이 숫자만 바꾸면 돼요.
  • if / else if / else 세 갈래 — 먼 구간(또는 실패), 아주 가까운 구간, 그 사이 구간을 나눕니다. 위에서부터 차례로 확인하므로 순서가 중요합니다. 첫 조건에서 cm < 0(실패)을 같이 걸러야 -1이 두 번째 조건 cm <= NEAR_CM으로 흘러가 경보가 울리는 일이 없어요.
  • map((long)cm, NEAR_CM, FAR_CM, MIN_INTERVAL, MAX_INTERVAL) — map은 정수를 받으므로 (long)cm으로 소수점을 버린 정수로 바꿔 넣습니다. 중간 구간에서만 실행되므로 입력 범위(10~100)를 벗어날 일이 없습니다.
  • millis() - lastBeep >= interval — 지난 삑으로부터 interval(ms)이 흘렀는지 확인합니다. 흘렀으면 지금 시각을 기록하고 삑 + LED 번쩍.
  • tone(BUZZER_PIN, 1000, BEEP_MS) 뒤의 delay(BEEP_MS) — tone은 기다리지 않으므로, 소리가 나는 동안 LED를 켜 두기 위해 같은 시간만큼 잠깐 기다린 뒤 LED를 끕니다.
  • 맨 끝의 delay(60) — 측정 사이 간격을 확보합니다. HC-SR04는 약 60ms보다 빠르게는 다시 쏘지 않는 것이 좋아요(앞선 초음파의 메아리가 다음 측정에 섞이지 않게).
동작이 어색할 때손을 대도 안 울리면 시리얼 모니터의 거리 값부터 보세요. 값이 -1.0만 나오면 센서 배선, 값은 잘 나오는데 소리가 안 나면 부저 쪽(핀 번호, 패시브/액티브 종류, 극성)이 원인입니다. 센서 문제인지 출력 문제인지 나눠서 확인하는 게 요령이에요.

7-4🚀 도전 과제

완성 코드를 고쳐서 기능을 추가해 보세요. 막히면 힌트를 열어보세요.

도전 1. 가까울수록 음도 높아지게 하기삑 소리의 주파수도 map으로 거리에 연결합니다. 가까울수록 큰 값이 되도록 출력 범위의 순서를 거꾸로 씁니다. 중간 구간의 tone 줄을 이렇게 바꿔 보세요. 
long freq = map((long)cm, NEAR_CM, FAR_CM, 2000, 500);   // 가까우면 2000Hz, 멀면 500Hz
tone(BUZZER_PIN, freq, BEEP_MS);
도전 2. 버튼으로 경보기 켜고 끄기2장의 토글 버튼을 추가합니다(D2 + GND, INPUT_PULLUP). 켜짐 상태를 저장하는 변수 bool armed를 두고, 버튼이 눌릴 때마다 뒤집은 뒤 loop() 맨 앞에서 if (!armed) { noTone(BUZZER_PIN); digitalWrite(LED_PIN, LOW); delay(60); return; }로 꺼진 상태를 처리하면 됩니다. 디바운스는 2장 millis 버전을 재사용하세요.
도전 3. 서보를 달아 레이더 만들기서보 위에 센서를 붙이고(테이프로 충분), 서보를 0~180도로 10도씩 돌리며 각도마다 거리를 시리얼에 찍습니다. 서보는 D9, 부저는 D8이라 서로 방해하지 않아요(Servo는 타이머1, tone은 타이머2를 사용). 서보와 센서가 함께 있으면 전류가 커지니 보드가 리셋되면 8장의 안전 수칙을 보세요. 
for (int angle = 0; angle <= 180; angle += 10) {
  myServo.write(angle);
  delay(300);                       // 서보가 도착할 시간
  float d = readDistanceCm();
  Serial.print(angle);
  Serial.print(" deg : ");
  Serial.println(d, 1);
}
도전 4. 값이 튀는 것을 줄이기 (평균 내기)초음파 값은 가끔 확 튑니다. 세 번 재서 유효한 값만 평균을 내면 훨씬 안정적이에요. loop() 맨 앞의 float cm = readDistanceCm(); 줄을 아래로 교체해 보세요. 
float sum = 0;
int n = 0;
for (int i = 0; i < 3; i++) {
  float v = readDistanceCm();
  if (v > 0) {          // 실패(-1)는 제외
    sum += v;
    n++;
  }
  delay(20);
}
float cm = (n > 0) ? sum / n : -1;

✅ 확인 문제

Q1. 경보기에서 "소리 간격 동안 delay로 쉬지 않고 millis를 쓴" 이유는?쉬는 동안에도 계속 거리를 재서 빠르게 반응하기 위해서입니다. delay 중에는 아두이노가 다른 일을 못 합니다.
Q2. 측정 실패(-1)를 먼저 걸러내지 않으면 어떤 일이 생길 수 있나요?-1이 "10cm 이내" 조건에 해당해 아무것도 없는데 경보가 울립니다. 그래서 첫 조건에 cm < 0을 포함했습니다.

안전 수칙

꼭 지키세요
  • 5V와 GND를 선으로 직접 연결하지 마세요. 단락(쇼트)이 나면 보드나 PC USB 포트가 상할 수 있습니다. 배선은 USB를 뽑고 하세요.
  • LED에는 항상 저항을 연결합니다.
  • 핀 하나에서 뽑는 전류는 20mA 이하로. 모터, 릴레이, 긴 LED 줄 같은 큰 부하는 핀에 바로 연결하면 안 되고 트랜지스터나 드라이버 모듈을 거쳐야 합니다.
  • 입력 핀에 5V보다 높은 전압을 넣지 마세요. 3.3V 부품과 5V 부품이 섞일 때는 전압을 꼭 확인합니다.
  • 서보를 두 개 이상 쓰거나 힘이 필요한 작업을 하면 USB(보드 5V)로는 전류가 모자랍니다. 서보 전원은 외부 전원(AA 충전지(니켈수소) 4개 팩(약 4.8V)이나 5V 어댑터 같은 안정된 5V 전원. 새 알카라인 건전지 4개는 6.4V까지 올라 SG90의 최대 6V를 넘을 수 있으니 피하세요)으로 따로 공급하고, 외부 전원의 GND를 아두이노 GND와 반드시 연결(공통 GND)하세요. GND를 이어 주지 않으면 신호의 기준이 달라서 서보가 엉뚱하게 움직입니다. 단, 외부 전원의 +는 아두이노 5V에 연결하지 않습니다.
  • 건전지와 충전지는 극성을 확인하고, 뜨거워지는 부품이 있으면 바로 전원을 뽑으세요.
